1. HTML — Structure

frontend/index.html

1 Doctype + root

Theory

First line tell browser "this is HTML5." Without it, browser go quirks mode and rendering get weird. The <html lang="en"> help screen readers + SEO.

Code

<!DOCTYPE html>
<html lang="en">

2 <head> — meta + stylesheet

Theory

<head> hold info about the page, not visible content. charset say "use UTF-8" so emoji + non-English text render correctly. The viewport meta is the one trick that make site responsive on phone. The <link> pull external CSS file.

Code

<head>
  <meta charset="UTF-8" />
  <meta name="viewport" content="width=device-width, initial-scale=1.0" />
  <title>TinyLink — URL Shortener</title>
  <link rel="stylesheet" href="style.css" />
</head>
Why viewport line? Without it, phones render at 980 px wide then shrink → tiny text. With it, layout adapt to actual screen.

3 Top navigation

Theory

Semantic tags = use the right tag for the job. <header> for top bar, <nav> for link group. Helps screen readers + SEO.

Code

<header class="topbar">
  <div class="brand">
    <span class="logo">🔗</span>
    <span class="brand-name">TinyLink</span>
  </div>
  <nav class="nav-links">
    <a href="#shorten">Shorten</a>
    <a href="#history">History</a>
    <a href="#about">About</a>
  </nav>
</header>

The href="#shorten" jump to element with id="shorten". No JS needed.

4 The form — heart of the app

Theory

A <form> group inputs and gives you a single submit event. We use type="url" so browser do basic validation + show URL keyboard on phones. novalidate tells browser "let JS handle the error message" (cleaner UI).

Code

<form id="shorten-form" class="shorten-form" novalidate>
  <input
    type="url"
    id="long-url"
    name="long"
    placeholder="https://example.com/..."
    required
    autocomplete="off" />
  <button type="submit">Shorten</button>
</form>

5 Result card — hidden by default

Theory

The hidden attribute is HTML5 standard way to hide element. JS will flip it (el.hidden = false) when result arrives. Better than display:none in CSS because it is semantic — assistive tech know element is hidden.

Code

<div class="result-card" id="result-card" hidden>
  <div class="result-row">
    <span class="result-label">Short URL</span>
    <a id="result-link" href="#" target="_blank" rel="noopener"></a>
  </div>
  <button class="copy-btn" id="copy-btn">Copy</button>
</div>
rel="noopener" on target="_blank" link = security best practice. Without it, new tab can hijack your tab via window.opener.

6 Script at the bottom

Theory

Putting <script> right before </body> means the DOM exists by the time JS runs. So document.querySelector('#form') finds the element. If you put script in <head> without defer, your selectors return null and you debug for an hour.

Code

  ...
  <script src="app.js"></script>
</body>
Alternative: <script src="app.js" defer></script> in head — also waits for DOM, plus loads in parallel. Either works.

2. CSS — Look + Layout

frontend/style.css

1 CSS variables (design tokens)

Theory

Variables on :root = global. Anywhere in CSS use var(--name). Big win: change color once, whole UI updates. Also makes dark/light theming trivial later.

Code

:root {
  --bg:        #0d1117;
  --accent:    #58a6ff;
  --radius:    10px;
  --shadow:    0 6px 20px rgba(0, 0, 0, 0.35);
}

.shorten-form button {
  background: var(--accent);     /* uses the token */
  border-radius: 8px;
}

2 Universal reset

Theory

Browsers ship with default margins on body, h1, etc. Different per browser. Reset zeros it so you control spacing. box-sizing: border-box = padding + border counted inside the width (intuitive). Without it, width:100% + padding overflow.

Code

* { box-sizing: border-box; margin: 0; padding: 0; }

3 Flexbox for the form

Theory

Flexbox = 1D layout (row or column). display:flex on parent → children align side by side. flex:1 on input means "take all leftover space." Button keeps natural width.

Code

.shorten-form {
  display: flex;
  gap: 10px;          /* space between children */
}
.shorten-form input  { flex: 1; }    /* grow to fill */
.shorten-form button { padding: 12px 24px; }

4 Grid for the "How it works" cards

Theory

Grid = 2D layout. auto-fit + minmax(220px, 1fr) = "as many columns as fit, each at least 220 px wide, expand evenly." Auto-responsive: 3 cards on desktop, 2 on tablet, 1 on phone — no media query needed.

Code

.cards {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(220px, 1fr));
  gap: 16px;
}

5 Gradient text trick

Theory

To paint text with a gradient, set background to gradient then make text transparent and "clip" the background to text shape. The -webkit- prefix needed for Safari + Chrome.

Code

.hero .accent {
  background: linear-gradient(135deg, #58a6ff, #d2a8ff);
  -webkit-background-clip: text;
  background-clip: text;
  color: transparent;
}

HTML side: <span class="accent">tiny</span>.

6 Keyframe animation on result card

Theory

@keyframes define stages. animation property apply them. Subtle motion (~250 ms) make UI feel alive without being distracting.

Code

  animation: pop-in 0.25s ease-out;
}

  from { opacity: 0; transform: translateY(6px); }
  to   { opacity: 1; transform: translateY(0); }
}

7 Responsive — media query

Theory

Media query = "apply these rules only when condition true." Common: viewport width. We collapse the form to vertical on phones.

Code

@media (max-width: 600px) {
  .hero h1      { font-size: 2rem; }
  .shorten-form { flex-direction: column; }
  .shorten-form button { width: 100%; }
}
Mobile-first alternative: design small first, then use min-width queries to add desktop styles. Either works — be consistent.

2 Base62 — moved to the Python backend

Theory

Original demo did Base62 in the browser, but a real shortener must encode the database id, and only the server knows that. So encoding moved to Python (see Python Backend section). The algorithm is identical: divide-mod loop, pick char at index n % 62, shrink n = floor(n / 62), repeat until n == 0, reverse.

Old JS version (kept here for reference)

const ALPHA = '0123456789abcdefghijklmnopqrstuvwxyz'
            + 'ABCDEFGHIJKLMNOPQRSTUVWXYZ';

function base62(n) {
  if (n === 0) return '0';
  let out = '';
  while (n > 0) {
    out = ALPHA[n % 62] + out;
    n = Math.floor(n / 62);
  }
  return out;
}
Frontend app.js no longer contains base62() — the server returns the ready-made code string in its JSON response.

3 URL validation with built-in URL class

Theory

Don't write regex for URLs. Browser has the URL constructor — it throws if string isn't a valid URL. We catch it and also require http(s) so user can't paste javascript: URLs.

Code

function isValidUrl(str) {
  try {
    const u = new URL(str);
    return u.protocol === 'http:' || u.protocol === 'https:';
  } catch {
    return false;
  }
}

4 Calling the Python backend with fetch

Theory

fetch() is the browser's built-in HTTP client. It returns a Promise<Response>, so we await it. The body must be a JSON string — that's why JSON.stringify(...). The matching FastAPI route accepts a Pydantic model with a long field (see Python Backend).

Code (now in app.js)

async function shorten(longUrl) {
  const res = await fetch('/api/shorten', {
    method:  'POST',
    headers: { 'Content-Type': 'application/json' },
    body:    JSON.stringify({ long: longUrl })
  });
  if (!res.ok) {
    const msg = await res.text().catch(() => '');
    throw new Error(`API ${res.status}: ${msg || 'request failed'}`);
  }
  return res.json();
}

Expected response shape

{
  "code":  "2k",
  "short": "http://localhost:8000/2k",
  "long":  "https://example.com/some/very/long/path"
}
Same-origin = no CORS headache. If the Python app serves frontend/ as static files, the browser sees one origin and fetch('/api/shorten') just works.

5 localStorage — persist history

Theory

localStorage = browser key-value store, persist across reloads. Only stores strings → use JSON.stringify to write, JSON.parse to read. Wrap in try/catch in case it's disabled (private mode).

Code

const STORAGE_KEY = 'tinylink.history';

function loadHistory() {
  try {
    return JSON.parse(localStorage.getItem(STORAGE_KEY)) || [];
  } catch { return []; }
}

function saveHistory(list) {
  localStorage.setItem(STORAGE_KEY, JSON.stringify(list));
}

function addToHistory(entry) {
  const list = loadHistory();
  list.unshift({ ...entry, at: Date.now() });
  saveHistory(list.slice(0, 20));   // keep last 20
  renderHistory();
}
localStorage cap is ~5 MB per origin. Don't store huge blobs there.

6 Render history — template literals

Theory

Build HTML string with backticks (template literal), then assign to .innerHTML. Quick + simple. Real frameworks (React, Vue) use virtual DOM — but for ~20 items this is fine.

Code

function renderHistory() {
  const list = loadHistory();
  historyList.innerHTML = '';

  if (list.length === 0) { emptyState.hidden = false; return; }
  emptyState.hidden = true;

  for (const entry of list) {
    const li = document.createElement('li');
    li.className = 'history-item';
    li.innerHTML = `
      <div class="history-meta">
        <a class="history-short" href="${entry.short}">${entry.short}</a>
        <span class="history-long">${entry.long}</span>
      </div>
      <div class="history-actions">
        <button data-action="copy" data-short="${entry.short}">📋</button>
        <button data-action="del"  data-code="${entry.code}">✕</button>
      </div>
    `;
    historyList.appendChild(li);
  }
}
If entry.long contained HTML, innerHTML would execute it (XSS). For trusted/own data fine. For user content from a public API, sanitize first or use textContent.

7 Event delegation for history buttons

Theory

Instead of attaching a listener to every button (20+ listeners as list grow), attach one to the parent <ul>. Inside, check what was clicked via e.target. Lighter, also works for items added later.

Code

historyList.addEventListener('click', (e) => {
  const btn = e.target.closest('button[data-action]');
  if (!btn) return;

  if (btn.dataset.action === 'copy') {
    copyText(btn.dataset.short, btn);
  } else if (btn.dataset.action === 'del') {
    deleteFromHistory(btn.dataset.code);
  }
});

data-* attributes are HTML5 standard way to attach custom data. Read in JS via btn.dataset.action etc.

8 The submit handler — full flow

Theory

This is where everything connect. Validate → disable button → call backend → show result → save history → re-enable button. try / finally guarantee button get re-enabled even if request fail.

Code

form.addEventListener('submit', async (e) => {
  e.preventDefault();                            // stop page reload
  clearError();
  resultCard.hidden = true;

  const longUrl = input.value.trim();
  if (!isValidUrl(longUrl)) {
    showError('Please enter a valid http(s) URL.');
    return;
  }

  submitBtn.disabled = true;
  submitBtn.textContent = 'Shortening…';

  try {
    const data = await mockShorten(longUrl);
    resultLink.href = data.short;
    resultLink.textContent = data.short;
    resultCard.hidden = false;
    addToHistory(data);
    input.value = '';
  } catch (err) {
    showError('Something went wrong. Try again.');
  } finally {
    submitBtn.disabled = false;
    submitBtn.textContent = 'Shorten';
  }
});
Linear flow with await pause at fetch step.

9 Clipboard API + feedback animation

Theory

Modern browsers expose navigator.clipboard.writeText(). Async (returns promise). Give visual feedback because clipboard write is invisible otherwise.

Code

async function copyText(text, btn) {
  try {
    await navigator.clipboard.writeText(text);
    if (btn) {
      const original = btn.textContent;
      btn.textContent = 'Copied!';
      btn.classList.add('copied');
      setTimeout(() => {
        btn.textContent = original;
        btn.classList.remove('copied');
      }, 1200);
    }
  } catch (err) { console.error('Clipboard failed', err); }
}
Clipboard API only works on HTTPS or localhost. Open the file with file:// and it fails silently.

2 SQLite table

Theory

One table. id is auto-increment integer — that's the number we Base62-encode. Storing long_url as TEXT keeps things simple.

Code

import sqlite3

conn = sqlite3.connect("backend/tinylink.db", check_same_thread=False)
conn.execute("""
  CREATE TABLE IF NOT EXISTS links (
    id        INTEGER PRIMARY KEY AUTOINCREMENT,
    long_url  TEXT    NOT NULL,
    created   DATETIME DEFAULT CURRENT_TIMESTAMP
  )
""")
conn.commit()
check_same_thread=False is fine for this demo (single process). For real production use SQLAlchemy + a connection pool.

3 Base62 in Python

Theory

Same divide-mod loop as the JS version, just cleaner because Python has built-in integer division and string.digits / string.ascii_letters in stdlib.

Code

import string

ALPHA = string.digits + string.ascii_lowercase + string.ascii_uppercase   # 62 chars

def base62(n: int) -> str:
    if n == 0:
        return "0"
    out = []
    while n > 0:
        n, r = divmod(n, 62)
        out.append(ALPHA[r])
    return "".join(reversed(out))

Quick check: base62(125) → "21", base62(10_000_000_000) → "aUKYOz". Same outputs as the JS version.

4 The two routes

Theory

Two endpoints cover the whole product:

  • POST /api/shorten — receive a long URL, insert row, return {code, short, long}.
  • GET /{code} — decode (just lookup by id), 302 redirect to original URL.

FastAPI uses Pydantic models to declare request/response shape. Type errors become 422 responses automatically.

Code

from fastapi import FastAPI, HTTPException, Request
from fastapi.responses import RedirectResponse
from fastapi.staticfiles import StaticFiles
from pydantic import BaseModel, HttpUrl

app = FastAPI()

class ShortenIn(BaseModel):
    long: HttpUrl                         # validates URL for free

class ShortenOut(BaseModel):
    code:  str
    short: str
    long:  str

# --- POST /api/shorten -------------------------------------------------
@app.post("/api/shorten", response_model=ShortenOut)
def create_short(body: ShortenIn, request: Request):
    cur = conn.execute("INSERT INTO links (long_url) VALUES (?)",
                       (str(body.long),))
    conn.commit()
    code = base62(cur.lastrowid)
    base = str(request.base_url).rstrip("/")
    return ShortenOut(code=code, short=f"{base}/{code}", long=str(body.long))

# --- GET /{code} -> 302 redirect --------------------------------------
def from_base62(s: str) -> int:
    n = 0
    for ch in s:
        n = n * 62 + ALPHA.index(ch)
    return n

@app.get("/{code}")
def follow(code: str):
    try:
        row_id = from_base62(code)
    except ValueError:
        raise HTTPException(404, "bad code")
    row = conn.execute("SELECT long_url FROM links WHERE id = ?",
                       (row_id,)).fetchone()
    if not row:
        raise HTTPException(404, "not found")
    return RedirectResponse(row[0], status_code=302)

# --- serve the frontend folder ----------------------------------------
app.mount("/", StaticFiles(directory="frontend", html=True), name="site")
Order matters: declare /api/... and /{code} before the catch-all app.mount("/"). FastAPI checks routes top-down.

Try it end-to-end:

  1. Paste a long URL → click Shorten.
  2. Frontend fires POST /api/shorten → Python inserts a row, returns {code, short, long}.
  3. Click the short link → browser hits GET /{code} → FastAPI 302-redirects to the original URL.
  4. History list in the UI is still cached in localStorage for instant render across reloads.
Clipboard API needs an HTTP origin. localhost counts, but opening index.html via file:// does not — always go through the uvicorn server.
