1. HTML

HyperText Markup Language · skeleton of page · required

What it does

HTML tag tell browser "this part is heading, this part is form, this part is button." No style, no logic. Just structure.

Basics

  • <tag>content</tag> — element with open + close.
  • Self-closing: <input />, <img />, <br />.
  • Attributes give extra info: <a href="/x">, <input type="url">.
  • Tree structure — every page is nested tags (DOM tree).

Visual — DOM tree

Every HTML doc = tree. JS later walk this tree.

Example — URL shortener form

<!DOCTYPE html>
<html>
  <head><title>Shorten</title></head>
  <body>
    <h1>URL Shortener</h1>
    <form id="f">
      <input type="url" name="long" required />
      <button>Shorten</button>
    </form>
    <p id="out"></p>
  </body>
</html>

3. JavaScript (Browser)

Client-side logic · DOM + fetch · required

What it does

JS run inside browser. Listen click, read input value, call API with fetch, update DOM with result.

Basics

  • Variables: let x = 5; const y = "hi";
  • Function: function add(a,b){ return a+b; } or arrow (a,b) => a+b.
  • DOM: document.querySelector('#out') grab element. .textContent = "x" set text.
  • Async: await fetch(url) wait for network. Need async on function.
  • Event: el.addEventListener('click', fn) run fn when click.

Visual — Event loop (why async matter)

JS single thread. Slow stuff (fetch) parked in Web APIs, callback fires later via queue.

Example — submit form, call API

const form = document.querySelector('#f');
const out  = document.querySelector('#out');

form.addEventListener('submit', async (e) => {
  e.preventDefault();
  const long = new FormData(form).get('long');

  const res = await fetch('/api/shorten', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ long: long })   // FastAPI expects { long: "..." }
  });
  const data = await res.json();
  out.textContent = 'Short: ' + data.short;
});

5. Python

Server-side language · runs FastAPI · required

What it does

Python interpreter run your code on the server. Reads files, listens on ports, talks to DB. Big standard library (sqlite3, json, string, datetime — all built in, no install). Massive ecosystem on PyPI for the rest.

Basics

  • Virtual env: python3 -m venv .venv → source .venv/bin/activate. Isolates project deps from system Python.
  • pip: package manager. pip install fastapi uvicorn[standard].
  • requirements.txt: pinned dep list. pip freeze > requirements.txt.
  • Type hints: def add(a: int, b: int) -> int: — optional, but FastAPI / Pydantic use them for validation.
  • async / await: async def + await for non-blocking I/O. Uvicorn runs the event loop.

Visual — Python runtime

Python code on the left. Uvicorn drives the async event loop and dispatches I/O.

Example — hello server (stdlib only, no framework)

from http.server import HTTPServer, BaseHTTPRequestHandler

class H(BaseHTTPRequestHandler):
    def do_GET(self):
        self.send_response(200)
        self.send_header("Content-Type", "text/plain")
        self.end_headers()
        self.wfile.write(b"Hello from Python")

HTTPServer(("", 8000), H).serve_forever()

Use FastAPI (next section) for real routing — this is just to show Python alone can serve HTTP.

6. FastAPI (+ Uvicorn)

Async Python web framework · required

What it does

FastAPI gives you decorator-based routing (@app.post('/path')), automatic JSON parsing, Pydantic validation, and free Swagger docs at /docs. Uvicorn is the ASGI server that actually opens the socket and runs the asyncio event loop.

Basics

  • Route: @app.get(path), @app.post(path), etc. The function below is the handler.
  • Request body: declare a Pydantic BaseModel as a parameter — FastAPI parses + validates JSON for free.
  • Path params: /links/{code} → arg code: str in the handler.
  • Middleware: app.add_middleware(...) for CORS, GZip, sessions, custom logging.
  • Run: uvicorn backend.main:app --reload --port 8000.

Visual — request pipeline

Pydantic catches bad input automatically — returns 422 before your handler runs.

Example — full shorten + redirect routes

from fastapi import FastAPI, HTTPException, Request
from fastapi.responses import RedirectResponse
from pydantic import BaseModel, HttpUrl

app = FastAPI()

class ShortenIn(BaseModel):
    long: HttpUrl                              # validated, 422 if bad

@app.post("/api/shorten")
def create_short(body: ShortenIn, request: Request):
    cur = conn.execute("INSERT INTO links (long_url) VALUES (?)",
                       (str(body.long),))
    conn.commit()
    code = base62(cur.lastrowid)
    base = str(request.base_url).rstrip("/")
    return {"code": code, "short": f"{base}/{code}", "long": str(body.long)}

@app.get("/{code}")
def follow(code: str):
    row = conn.execute("SELECT long_url FROM links WHERE id = ?",
                       (from_base62(code),)).fetchone()
    if not row:
        raise HTTPException(404, "not found")
    return RedirectResponse(row[0], status_code=302)
Open http://localhost:8000/docs — FastAPI auto-builds a Swagger UI from these decorators + Pydantic models. Click Try it out to fire real requests against your own API.

7. SQLite

File-based relational DB · source of truth · required

What it does

Stores every short link in a single .db file on disk. ACID transactions, indexes, constraints — same shape as MySQL/Postgres, just zero setup. Built into Python's stdlib as sqlite3. Perfect to learn on; swap to MySQL or Postgres later by changing the connection URL.

Basics

  • One file: tinylink.db. Copy it = backup. No server process to run.
  • Schema: shape of table (columns + types). SQLite is loose on types (type affinity), but you still declare them.
  • PRIMARY KEY: unique row id. INTEGER PRIMARY KEY AUTOINCREMENT = auto-counter.
  • INDEX: B-tree for fast lookup. Same idea as any SQL DB.
  • Limit: single-writer (one INSERT/UPDATE at a time). Fine for a hobby project; switch to Postgres for high write concurrency.

Visual — table + index

PRIMARY KEY auto-builds the index. Redirect path = decode code → id → row lookup.

Example — schema (SQLite flavour)

CREATE TABLE IF NOT EXISTS links (
  id        INTEGER PRIMARY KEY AUTOINCREMENT,
  long_url  TEXT NOT NULL,
  created   DATETIME DEFAULT CURRENT_TIMESTAMP
);

Example — connect from Python (stdlib, no install)

import sqlite3

conn = sqlite3.connect("backend/tinylink.db", check_same_thread=False)
conn.row_factory = sqlite3.Row     # rows act like dicts
Want to inspect the DB? Run sqlite3 backend/tinylink.db from the terminal and type .tables, then SELECT * FROM links;

8. SQL

Query language for SQLite / Postgres / MySQL · required

What it does

SQL declarative — say what rows you want, engine figure out how. Four big verbs: SELECT, INSERT, UPDATE, DELETE (CRUD). Same language across SQLite, Postgres, MySQL — small dialect differences only.

Basics

VerbUseExample
SELECTreadSELECT long_url FROM links WHERE code = ?
INSERTcreateINSERT INTO links (long_url) VALUES (?)
UPDATEmodifyUPDATE links SET expires_at = ? WHERE id = ?
DELETEremoveDELETE FROM links WHERE expires_at < NOW()

Important — parameterized query

Never concat user input into SQL string → SQL injection. Use placeholder ?, pass values as a tuple.

BAD: f"SELECT * FROM links WHERE id = {user_input}"
GOOD: conn.execute("SELECT * FROM links WHERE id = ?", (user_input,))

Example — Python call to SQLite

import sqlite3

conn = sqlite3.connect("backend/tinylink.db", check_same_thread=False)
conn.row_factory = sqlite3.Row

def lookup(id_: int) -> str | None:
    row = conn.execute(
        "SELECT long_url FROM links WHERE id = ?", (id_,)
    ).fetchone()
    return row["long_url"] if row else None

EXPLAIN — see if index used (SQLite)

EXPLAIN QUERY PLAN
SELECT long_url FROM links WHERE id = 125;
-- SEARCH links USING INTEGER PRIMARY KEY (rowid=?)   ✅ index hit
-- SCAN links                                          ⚠ full scan

9. Redis

In-memory key-value store · cache · recommended

What it does

Redis hold hot data in RAM. Key → value. Sub-millisecond. Use it so redirect skip slow DB on common codes.

Basics

  • Commands: SET key val, GET key, DEL key, EXPIRE key 3600.
  • TTL: set expiry so cache not grow forever.
  • Cache-aside pattern: app check cache first, miss → DB, then fill cache.
  • Volatile by default (data lost on restart unless persistence on). OK for cache role.

Visual — cache-aside read path

First read = slow (DB). Next reads = fast (Redis). Hit rate >90% typical.

Example — cache-aside in FastAPI (redis-py)

import redis
from fastapi import HTTPException
from fastapi.responses import RedirectResponse

r = redis.Redis(host="localhost", port=6379, decode_responses=True)

@app.get("/{code}")
def follow(code: str):
    url = r.get(code)                              # 1. cache
    if not url:
        url = lookup(from_base62(code))             # 2. DB
        if not url:
            raise HTTPException(404)
        r.setex(code, 3600, url)                    # 3. fill, 1h TTL
    return RedirectResponse(url, status_code=302)

Install: pip install redis. Run Redis locally with docker run -p 6379:6379 redis:7-alpine.

10. Base62 Encoding

Algorithm · turn big integer ID into short string · required

What it does

DB give you incrementing id (1, 2, 3, ...). Showing "tiny.io/3829473829" ugly. Convert id to base 62 → use 0-9, a-z, A-Z → 6 chars cover ~56 billion links.

Basics

  • Base 10 = 10 digits. Base 62 = 62 chars (0-9, a-z, A-Z).
  • To encode: repeatedly divide by 62, take remainder as char.
  • Reversible: base62 string → int with reverse map (but you usually don't need reverse — lookup table by string).
  • Length: 6 chars → 62^6 = 56,800,235,584. Plenty.

Visual — encode 125 → "21"

Divide-mod loop until quotient = 0. Collect remainders, reverse.

Example — Python implementation (lives on the backend)

import string

ALPHA = string.digits + string.ascii_lowercase + string.ascii_uppercase   # 62 chars

def base62(n: int) -> str:
    if n == 0:
        return "0"
    out = []
    while n > 0:
        n, r = divmod(n, 62)
        out.append(ALPHA[r])
    return "".join(reversed(out))

def from_base62(s: str) -> int:
    n = 0
    for ch in s:
        n = n * 62 + ALPHA.index(ch)
    return n

base62(125)             # "21"
base62(100_000)         # "q0U"
base62(10_000_000_000)  # "aUKYOz"
from_base62("21")       # 125  (round-trip for redirect)
Encoding lives on the backend because only the server knows the DB id. The browser never computes the code itself — it just receives it in the JSON response.

11. Docker

Containers · run app same everywhere · recommended

What it does

Docker pack app + all deps into image. Run image as container — isolated lightweight process. No more "works on my machine."

Basics

  • Image: blueprint, read-only. Built from Dockerfile.
  • Container: running instance of image.
  • Dockerfile: recipe — base image + copy code + install deps + start command.
  • docker-compose.yml: define multi-service stack (app + Redis, plus Postgres if you outgrow SQLite) in one file.

Visual — image vs container

Example — Dockerfile for the Python app

FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY backend ./backend
COPY frontend ./frontend
EXPOSE 8000
CMD ["uvicorn", "backend.main:app", "--host", "0.0.0.0", "--port", "8000"]

Example — docker-compose.yml (app + optional cache)

services:
  app:
    build: .
    ports: ["8000:8000"]
    volumes: ["./backend:/app/backend"]    # SQLite file persists here
    depends_on: [cache]
    environment:
      REDIS_HOST: cache
  cache:
    image: redis:7-alpine

Then docker compose up brings both services up. SQLite lives inside the mounted volume — no separate DB container needed.

Outgrew SQLite? Swap in postgres:16 as a third service and update the connection string. Schema + queries hardly change.

13. Nginx

Reverse proxy + TLS + static files · recommended for prod

What it does

Sit in front of Uvicorn. Handle HTTPS (TLS termination), serve static files fast, rate-limit, load-balance to multiple Uvicorn worker processes.

Basics

  • Reverse proxy: client → Nginx → Uvicorn. Client never see the Python process directly.
  • upstream: backend pool definition.
  • location: route block, match by path.
  • proxy_pass: forward request to upstream.

Visual — Nginx in front

Example — nginx.conf snippet

upstream app {
  server app1:8000;     # uvicorn workers
  server app2:8000;
}

server {
  listen 443 ssl;
  server_name tiny.io;
  ssl_certificate     /etc/letsencrypt/live/tiny.io/fullchain.pem;
  ssl_certificate_key /etc/letsencrypt/live/tiny.io/privkey.pem;

  location / {
    proxy_pass http://app;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
  }
}
Tip: in dev you don't need Nginx at all. uvicorn ... --workers 4 already runs multiple processes. Add Nginx when you need HTTPS or want to serve big static files efficiently.

14. Testing & Load (pytest + k6)

Unit test logic + load test the API · strongly recommended

What it does

  • pytest: Python's testing tool. Plain def test_* functions, assert statements, rich plugin ecosystem. Pair with httpx + FastAPI's TestClient for API tests.
  • k6: scriptable load testing in JS. Language-agnostic — fires HTTP at any server. Throw 1000 req/sec, see latency + error rate.

Visual — test pyramid

Many cheap fast unit tests at bottom. Few expensive end-to-end at top.

Example — pytest unit test for base62

from backend.main import base62, from_base62

def test_encodes_zero():
    assert base62(0) == "0"

def test_encodes_125():
    assert base62(125) == "21"

def test_round_trip():
    for n in [1, 125, 100_000, 10_000_000_000]:
        assert from_base62(base62(n)) == n

Example — API test with FastAPI's TestClient

from fastapi.testclient import TestClient
from backend.main import app

client = TestClient(app)

def test_shorten_and_follow():
    res = client.post("/api/shorten", json={"long": "https://example.com"})
    assert res.status_code == 200
    code = res.json()["code"]

    res2 = client.get(f"/{code}", follow_redirects=False)
    assert res2.status_code == 302
    assert res2.headers["location"] == "https://example.com"

Install: pip install pytest httpx. Run: pytest -v.

Example — k6 load script

import http from 'k6/http';
import { check, sleep } from 'k6';

export const options = {
  vus: 100,           // 100 virtual users
  duration: '30s',
};

export default function () {
  const res = http.get('http://localhost:8000/2k', { redirects: 0 });
  check(res, { 'is 302': r => r.status === 302 });
  sleep(0.1);
}
Run k6 run load.js. Watch http_req_duration p(95). With Redis cache, p95 should stay under ~5 ms.
