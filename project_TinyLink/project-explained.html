0. Big picture — one request, end to end

Two flows: shorten (POST) and follow (GET /{code}). Read this once; every later section makes sense in this frame.

Solid blue = data path. Dashed green = static-file serve. base62.py is a pure function called inside FastAPI; no separate process.

Flow 1 — shorten

1. User types URL, clicks Shorten      (frontend/app.js: submit handler)
2. fetch() POST /api/shorten           ({ "long": "https://..." })
3. Uvicorn accepts socket              (ASGI server)
4. FastAPI parses JSON via Pydantic    (ShortenIn, validates HttpUrl)
5. Handler INSERTs row → lastrowid     (backend/main.py + db.py)
6. encode(lastrowid)                   (backend/base62.py)
7. Response JSON: { code, short, long } (Pydantic ShortenOut serialises)
8. JS renders the short link + saves   (history list in localStorage)

Flow 2 — follow

1. Someone hits  http://host:8000/2k
2. FastAPI route GET /{code} matches    (RESERVED check excludes /docs etc.)
3. decode("2k") → int id                (backend/base62.py)
4. SELECT long_url WHERE id = ?         (backend/db.py connection)
5. RedirectResponse(long_url, 302)      (browser follows to original URL)

1. backend/base62.py

Pure algorithm. No I/O, no framework. Convert a non-negative integer to a compact string and back.

🔢backend/base62.py Python

Why base 62?

DB row ids count up: 1, 2, 3, … Showing tiny/3829473829 is ugly and predictable. We need short, URL-safe codes. Base 62 uses 62 characters — every digit (10) + every lowercase letter (26) + every uppercase letter (26). All URL-safe, no punctuation. 6 characters of base 62 cover 626 ≈ 56.8 billion distinct codes.

Encoding loop: divmod by 62, collect remainders, reverse. Same pattern as base-10 ↔ binary conversion.

Code, block by block

"""Base62 encode/decode for short codes.

DB hands us monotonic integer ids (1, 2, 3, ...). We turn each id into a
compact string using 62 symbols (0-9, a-z, A-Z). 6 chars = 56.8B possible
codes -- enough for any hobby project.
"""
Module docstring. Triple-quoted string sitting alone at the top of a Python file becomes module.__doc__. Documents what this file does. Pure text; no runtime behaviour. Helpful when someone runs help(backend.base62) in a REPL.
import string
Import the standard-library string module. Ships with Python, no install. We only need its prebuilt constants string.digits, string.ascii_lowercase, string.ascii_uppercase — saves writing the alphabet out by hand and avoids typos.
ALPHABET = string.digits + string.ascii_lowercase + string.ascii_uppercase
BASE = len(ALPHABET)
_INDEX = {ch: i for i, ch in enumerate(ALPHABET)}
Module-level constants.
  • ALPHABET = the 62-character string "0123…9abc…zABC…Z". The position of each character in this string is its base-62 value.
  • BASE = 62. Using len(ALPHABET) instead of a hard-coded 62 means if you ever swap to a different alphabet (e.g. exclude lookalikes 0/O, 1/l), BASE updates itself.
  • _INDEX = a dict mapping every character back to its integer value, built with a dict comprehension. enumerate(ALPHABET) yields (0, "0"), (1, "1"), … (61, "Z"). Leading underscore is a Python convention meaning "private — don't import this directly."
Lookup is now O(1) — decode can ask _INDEX[ch] instead of ALPHABET.index(ch) which is O(n). 
def encode(n: int) -> str:
    if n < 0:
        raise ValueError("base62 only encodes non-negative integers")
    if n == 0:
        return ALPHABET[0]
Function signature + early returns.
  • def encode(n: int) -> str: — type hints tell readers (and tools like mypy) that n should be an int and the return value is a str. Hints don't enforce types at runtime; they're documentation that tooling can lint.
  • if n < 0: raise ValueError(...) — guard against meaningless input. raise throws an exception that propagates upward until something catches it. SQLite ids start at 1, so we should never hit this in practice; it's a defensive net for future callers.
  • if n == 0: return ALPHABET[0] — the loop below stops when n == 0, so without this guard it would return an empty string for input 0. Edge case: ids in our schema start at 1, but the algorithm should still be correct in isolation.
    out = []
    while n > 0:
        n, r = divmod(n, BASE)
        out.append(ALPHABET[r])
    return "".join(reversed(out))
The divide-and-mod loop.
  • out = [] — empty list to collect characters.
  • divmod(n, BASE) — one builtin call that returns (n // 62, n % 62). Faster and clearer than two separate operations. The tuple-unpack n, r = ... updates n to the quotient and stores the remainder in r.
  • out.append(ALPHABET[r]) — translate the remainder (0–61) into its alphabet character and stash it.
  • Loop ends when n reaches 0.
  • reversed(out) — we collected the least-significant digit first, so reverse before joining. "".join(...) concatenates the list into a single string with no separator.
Example walkthrough for n = 125:
iter 1 → divmod(125,62) = (2,1), out = ["1"], n = 2.
iter 2 → divmod(2,62) = (0,2), out = ["1","2"], n = 0 → stop.
reversed → ["2","1"] → "21". 
def decode(s: str) -> int:
    n = 0
    for ch in s:
        if ch not in _INDEX:
            raise ValueError(f"invalid base62 character: {ch!r}")
        n = n * BASE + _INDEX[ch]
    return n
Reverse direction. Same idea as parsing base-10: each character bumps the running total up one position. n = n*62 + value is identical in spirit to n = n*10 + digit for decimal.
  • ch not in _INDEX — reject anything that isn't a digit/letter. Without this check, garbage input would silently return wrong ids.
  • {ch!r} — the !r conversion calls repr() on the value so the error shows '!' not just !. Easier to spot whitespace bugs.
  • This is the function called on the redirect path: GET /2k → decode("2k") = 125 → SELECT … WHERE id = 125.
Why not just store the code as a column? You could — generate a random 6-char string and put it in a code TEXT UNIQUE column. The base62-from-id trick avoids collisions entirely (every id is unique → every code is unique) and skips an extra index, but it does leak monotonic order. For a learning project, the simpler scheme wins.

2. backend/db.py

Open one SQLite file, ensure the schema exists, hand back a connection object. That's it.

🗄️backend/db.py Python · sqlite3 stdlib

The data model

Three columns. The short code is not stored — it's computed from id by base62.
"""SQLite connection + schema bootstrap.

One file (tinylink.db). One table (links). Connection is shared across
threads since FastAPI's default thread pool may dispatch handlers from
different threads -- check_same_thread=False allows that, and we serialise
writes via SQLite's own lock.
"""
Module docstring. Explains the threading caveat so the next reader knows why check_same_thread=False is set (see below).
import os
import sqlite3
from pathlib import Path
Three stdlib imports — zero install required.
  • os — read environment variables. Lets the DB path be overridden by TINYLINK_DB.
  • sqlite3 — the actual database driver. Python bundles SQLite.
  • pathlib.Path — modern object-oriented file paths. Path(...) / "name" is cleaner than os.path.join.
DB_PATH = Path(os.environ.get("TINYLINK_DB", Path(__file__).parent / "tinylink.db"))
Decide where the DB file lives.
  • os.environ.get("TINYLINK_DB", <default>) — read the env var if set, else use the default. This is how the test suite redirects the DB to a tmp path without editing code.
  • __file__ — the path of this source file at runtime. Path(__file__).parent = the backend/ folder. Joining with "tinylink.db" gives an absolute path that works whether you launch from project root or anywhere else.
  • Wrapping the whole expression in Path(...) normalises the result regardless of whether the env var was a string or already a Path.
SCHEMA = """
CREATE TABLE IF NOT EXISTS links (
    id        INTEGER PRIMARY KEY AUTOINCREMENT,
    long_url  TEXT NOT NULL,
    created   DATETIME DEFAULT CURRENT_TIMESTAMP
);
"""
The schema, as a Python string holding raw SQL.
  • CREATE TABLE IF NOT EXISTS — idempotent. Safe to run on every startup; if the table already exists, this is a no-op.
  • id INTEGER PRIMARY KEY AUTOINCREMENT — SQLite-special: the PK column doubles as the implicit rowid. AUTOINCREMENT guarantees ids are never reused even if rows are deleted (without it, SQLite may recycle the highest deleted id).
  • long_url TEXT NOT NULL — string column, can't be null. Validation also happens upstream in Pydantic, but a DB-level constraint is a backstop.
  • created DATETIME DEFAULT CURRENT_TIMESTAMP — auto-fills with the row's insertion time if the INSERT doesn't supply one. We never do, so every row is automatically time-stamped.
def connect() -> sqlite3.Connection:
    conn = sqlite3.connect(DB_PATH, check_same_thread=False)
    conn.row_factory = sqlite3.Row
    conn.execute("PRAGMA journal_mode = WAL;")
    conn.executescript(SCHEMA)
    conn.commit()
    return conn
The connection factory — five small but loaded lines.
  • sqlite3.connect(DB_PATH, …) — opens (or creates) the file and returns a Connection object that owns the underlying file handle.
  • check_same_thread=False — by default, sqlite3 forbids using a connection from a thread other than the one that created it. FastAPI/Uvicorn may dispatch handlers from a worker thread pool, so we disable the check. Safe because SQLite itself uses a file-level lock — only one writer at a time, readers don't block.
  • row_factory = sqlite3.Row — rows come back as dict-like objects: row["long_url"] instead of row[0]. Major readability win in main.py.
  • PRAGMA journal_mode = WAL; — switch SQLite from rollback-journal to write-ahead-logging. WAL lets readers and one writer run concurrently. A common perf tweak.
  • conn.executescript(SCHEMA) — runs the multi-statement schema script. execute only takes one statement; executescript handles many separated by ;.
  • conn.commit() — DDL doesn't strictly need commit in SQLite's autocommit-ish mode, but it's harmless and explicit.
  • return conn — the caller (main.py) holds onto this single shared connection.
One connection vs a pool. For high traffic, share a single connection only for reads; or move to aiosqlite / a real RDBMS with a connection pool. For this learning project, one shared sync connection plus WAL is plenty.

3. backend/main.py

The FastAPI app: middleware, static-file mount, Pydantic models, and the four routes.

🚀backend/main.py Python · FastAPI

Request pipeline

Each stage either passes the request along or short-circuits with an error response. Bad JSON dies at Pydantic — your handler never sees it.

Block-by-block

"""TinyLink FastAPI app.

Routes:
    GET  /                      -> serve frontend index.html
    POST /api/shorten           -> create short code for a long URL
    GET  /api/links/{code}      -> meta lookup (JSON, no redirect)
    GET  /{code}                -> 302 redirect to long URL
"""
Docstring as route table. Treating the docstring as a tiny README means anyone opening the file sees the API shape immediately, without scrolling for the @app decorators.
from pathlib import Path

from fastapi import FastAPI, HTTPException, Request
from fastapi.middleware.cors import CORSMiddleware
from fastapi.responses import FileResponse, RedirectResponse
from fastapi.staticfiles import StaticFiles
from pydantic import BaseModel, HttpUrl

from .base62 import decode, encode
from .db import connect
Imports, grouped by source. Python convention: stdlib first, third-party next, local last. A blank line between groups.
  • FastAPI — the framework class. HTTPException — raise this to short-circuit with a status code. Request — gives access to URL, headers, base URL.
  • CORSMiddleware — adds Access-Control-Allow-* headers so a browser at a different origin (e.g. dev frontend on port 5173) can call this API.
  • FileResponse — streams a file from disk. RedirectResponse — sends a 3xx with a Location header.
  • StaticFiles — a mountable ASGI app that serves a directory.
  • BaseModel, HttpUrl — Pydantic for declarative schema + validation. HttpUrl is a special string type that only accepts well-formed http/https URLs.
  • from .base62 import … — the dot means "from this package". Equivalent to from backend.base62 import … when run as uvicorn backend.main:app.
RESERVED = {"api", "static", "docs", "redoc", "openapi.json", "favicon.ico"}

FRONTEND_DIR = Path(__file__).resolve().parent.parent / "frontend"
Two module-level constants.
  • RESERVED — a set (curly braces, no key:value) of path segments we refuse to treat as short codes. Without this, hitting /docs might run the redirect logic and try to decode "docs" as base62. We check membership in O(1).
  • FRONTEND_DIR — .resolve() turns the path absolute, then .parent.parent climbs from backend/main.py → backend/ → project root, then joins frontend. This makes the path independent of where you launch the process.
app = FastAPI(title="TinyLink", version="1.0.0")

app.add_middleware(
    CORSMiddleware,
    allow_origins=["*"],
    allow_methods=["GET", "POST"],
    allow_headers=["*"],
)

app.mount("/static", StaticFiles(directory=FRONTEND_DIR), name="static")

conn = connect()
Construct the app, attach middleware, mount static dir, open DB.
  • FastAPI(title=…, version=…) — these show up on the auto-generated Swagger UI at /docs.
  • add_middleware(CORSMiddleware, …) — wraps every response. Headers signal browsers that cross-origin requests are OK. Asterisk origins is fine for a public read-only redirect API; tighten in production.
  • app.mount("/static", StaticFiles(directory=…)) — mounts a sub-app at /static. Any request whose path starts with /static/ is served from frontend/ as a raw file. Mounts are checked before routes during URL resolution, so this doesn't conflict with /{code}.
  • conn = connect() — open the DB once, at import time. Every handler reuses this connection. Module-level state is a hot debate in FastAPI; for a small app, this is fine.
class ShortenIn(BaseModel):
    long: HttpUrl

class ShortenOut(BaseModel):
    code: str
    short: str
    long: str
Pydantic models = the API contract.
  • ShortenIn — what the POST body must look like. Declaring long: HttpUrl means Pydantic will reject anything that isn't an http/https URL and FastAPI will respond with HTTP 422 automatically, before your handler runs.
  • ShortenOut — the response shape. FastAPI also uses these to generate the OpenAPI schema visible at /docs.
  • Field types in the response are plain str (not HttpUrl) so the JSON is a plain string and tools that consume it don't have to know about a custom URL class.
@app.get("/", include_in_schema=False)
def index() -> FileResponse:
    return FileResponse(FRONTEND_DIR / "index.html")
Serve the frontend at the root URL.
  • @app.get("/") — register a handler for GET /. The function name (index) is not magic; FastAPI uses it as the OpenAPI operationId.
  • include_in_schema=False — hides this route from /docs because it's an HTML serve, not part of the JSON API.
  • FileResponse — sets Content-Type: text/html from the file extension, streams the bytes, sends proper Content-Length and ETag headers. No need to read the file yourself.
@app.post("/api/shorten", response_model=ShortenOut)
def create_short(body: ShortenIn, request: Request) -> ShortenOut:
    long_url = str(body.long)
    cur = conn.execute(
        "INSERT INTO links (long_url) VALUES (?)",
        (long_url,),
    )
    conn.commit()
    code = encode(cur.lastrowid)
    base = str(request.base_url).rstrip("/")
    return ShortenOut(code=code, short=f"{base}/{code}", long=long_url)
The shorten endpoint.
  • @app.post("/api/shorten", response_model=ShortenOut) — declares method, path, and the schema FastAPI should validate/serialise the response against. If your code returns a dict missing code, FastAPI raises an internal error during serialisation.
  • body: ShortenIn — because the type is a Pydantic model, FastAPI knows to read the request body as JSON and parse it. If you'd written body: int, it would read from a query string instead.
  • request: Request — FastAPI sees this special type and injects the raw Request. Used here to build the absolute short URL.
  • str(body.long) — HttpUrl is its own type; we cast to str for the DB and JSON response.
  • conn.execute("…?…", (long_url,)) — the ? is a parameter placeholder. SQLite substitutes the values after parsing the SQL, which makes injection impossible. The trailing comma in (long_url,) is required to make it a tuple (one-element tuples need that comma).
  • conn.commit() — make the INSERT durable. Without this, the row may sit in an uncommitted transaction.
  • cur.lastrowid — the autoincrement id SQLite just assigned. Pass it through encode() to get the short code.
  • str(request.base_url).rstrip("/") — base_url is something like http://localhost:8000/; strip the trailing slash so we don't end up with //code.
  • return ShortenOut(…) — building the model explicitly is equivalent to returning a dict; this form is type-checked by IDEs.
@app.get("/api/links/{code}")
def link_meta(code: str) -> dict:
    if code in RESERVED:
        raise HTTPException(404, "not found")
    try:
        link_id = decode(code)
    except ValueError:
        raise HTTPException(400, "invalid code")
    row = conn.execute(
        "SELECT id, long_url, created FROM links WHERE id = ?",
        (link_id,),
    ).fetchone()
    if not row:
        raise HTTPException(404, "not found")
    return {"code": code, "long": row["long_url"], "created": row["created"]}
Meta endpoint — returns JSON instead of redirecting. Useful for an admin UI or debugging without triggering the actual redirect.
  • {code} in the path becomes the function arg code: str. FastAPI parses path params from URL segments.
  • raise HTTPException(404, …) — short-circuit. FastAPI turns this into {"detail":"not found"} with the right status.
  • try/except ValueError — decode raises if a non-alphabet character appears. We turn that into a 400 (client sent bad input) instead of letting Python's traceback leak.
  • .fetchone() returns either the first row or None. None → 404.
  • row["long_url"] works because we set row_factory = sqlite3.Row in db.py.
@app.get("/{code}", include_in_schema=False)
def follow(code: str) -> RedirectResponse:
    if code in RESERVED:
        raise HTTPException(404, "not found")
    try:
        link_id = decode(code)
    except ValueError:
        raise HTTPException(404, "not found")
    row = conn.execute(
        "SELECT long_url FROM links WHERE id = ?",
        (link_id,),
    ).fetchone()
    if not row:
        raise HTTPException(404, "not found")
    return RedirectResponse(row["long_url"], status_code=302)
The catch-all redirect. Last route declared, registered after every more-specific route, so it only fires when nothing else matched.
  • status_code=302 = "Found", a temporary redirect. Browsers don't cache it permanently. Use 301 if you really want permanent caching, but 302 is friendlier when you might want to change destinations later (analytics rewrites, etc.).
  • Bad code paths return 404 (not 400) here because, from the user's perspective, a URL like tiny.io/abc!!! is just "not a real short link" — same UX as a deleted link.
Why are the handlers def, not async def? SQLite's stdlib driver is synchronous. Using async def here would let blocking calls stall the event loop. FastAPI runs sync handlers in a thread pool, which is the right move for a sync DB driver. Switch to async def only when you're calling async APIs (e.g. aiosqlite, asyncpg, httpx.AsyncClient).

4. backend/__init__.py

An empty file with a very specific job.

📦backend/__init__.py Python · empty

This file is intentionally blank. Its presence in backend/ tells Python "treat this directory as a package." Once it exists, you can write from backend.main import app and from .base62 import encode. Without it, modern Python still works in many cases (PEP 420 namespace packages), but having an explicit __init__.py avoids weirdness with tools like pytest discovering modules.

You can put startup code or re-exports here later (e.g. from .main import app to allow from backend import app), but keeping it empty is the cleanest default.

The "set sane defaults" block.
  • * — universal selector. Zeroing default margin/padding kills browser quirks.
  • box-sizing: border-box — width includes padding and border. Without this, a 100px-wide box with 10px padding actually measures 120px. Industry standard.
  • scroll-behavior: smooth — when an anchor link is clicked, smooth-scroll instead of jumping.
  • font-family — a stack. The browser picks the first one that exists on the user's system. Apple's native font, then Microsoft's, then Android's, then a generic fallback.
  • min-height: 100vh; display: flex; flex-direction: column; — the "sticky footer" trick: body fills the viewport vertically and children flow top to bottom. Footer can margin-top: auto to glue itself to the bottom.

2. URL validation

function isValidUrl(str) {
  try {
    const u = new URL(str);
    return u.protocol === 'http:' || u.protocol === 'https:';
  } catch {
    return false;
  }
}
Use the built-in URL parser.
  • new URL(str) throws if the string is malformed; the try/catch turns that into a boolean.
  • Restricting to http(s) prevents users from pasting javascript: or data: URLs that the server doesn't need to deal with.
  • The server also validates with Pydantic's HttpUrl. Belt-and-suspenders.

3. Real backend call

async function shorten(longUrl) {
  const res = await fetch('/api/shorten', {
    method:  'POST',
    headers: { 'Content-Type': 'application/json' },
    body:    JSON.stringify({ long: longUrl })
  });
  if (!res.ok) {
    const msg = await res.text().catch(() => '');
    throw new Error(`API ${res.status}: ${msg || 'request failed'}`);
  }
  return res.json();
}
Network call, line by line.
  • async function — turns the function into one that always returns a Promise. Lets you use await inside.
  • fetch(url, options) — Browser API for HTTP. Returns a Promise that resolves to a Response object.
  • method: 'POST' — HTTP verb; matches the backend's @app.post.
  • headers: { 'Content-Type': 'application/json' } — tells the server how to decode the body. Without this, FastAPI can't parse the JSON.
  • body: JSON.stringify({ long: longUrl }) — turn a JS object into a JSON string. The shape { long: ... } matches Pydantic's ShortenIn model.
  • res.ok — true if status is 200–299. fetch does not throw on 4xx/5xx, so this manual check is required.
  • await res.text().catch(() => '') — read the error body, but if reading fails, fall back to an empty string. Chaining .catch on a Promise inside an await is a clean way to swallow a secondary failure.
  • throw new Error(…) — surfaces a meaningful message to the caller's try/catch.
  • res.json() — parse the response body as JSON. Also async.

4–5. History helpers

function loadHistory() {
  try {
    return JSON.parse(localStorage.getItem(STORAGE_KEY)) || [];
  } catch {
    return [];
  }
}
function saveHistory(list) {
  localStorage.setItem(STORAGE_KEY, JSON.stringify(list));
}
function addToHistory(entry) {
  const list = loadHistory();
  list.unshift({ ...entry, at: Date.now() });
  saveHistory(list.slice(0, 20));
  renderHistory();
}
localStorage as a tiny database.
  • localStorage.getItem(key) returns a string or null. JSON.parse(null) happens to return null, so the || [] fallback handles both "never saved" and "empty save."
  • try/catch guards against the user manually corrupting storage.
  • list.unshift(x) — push x at the front. Newest first.
  • { ...entry, at: Date.now() } — object spread copies entry and tacks on a timestamp without mutating the original.
  • list.slice(0, 20) — keep only the latest 20. Cheap quota cap.
function renderHistory() {
  const list = loadHistory();
  historyList.innerHTML = '';

  if (list.length === 0) {
    emptyState.hidden = false;
    return;
  }
  emptyState.hidden = true;

  for (const entry of list) {
    const li = document.createElement('li');
    li.className = 'history-item';
    li.innerHTML = `
      <div class="history-meta">
        <a class="history-short" href="${entry.short}" target="_blank" rel="noopener">${entry.short}</a>
        <span class="history-long" title="${entry.long}">${entry.long}</span>
      </div>
      <div class="history-actions">
        <button class="icon-btn" data-action="copy" data-short="${entry.short}" title="Copy">📋</button>
        <button class="icon-btn del" data-action="del" data-code="${entry.code}" title="Delete">✕</button>
      </div>
    `;
    historyList.appendChild(li);
  }
}
Re-render the entire list on every change. Cheap for ≤20 items and keeps state mental-model simple (data → DOM, one direction).
  • historyList.innerHTML = '' — wipe children. Faster than removing them one by one.
  • document.createElement('li') + appendChild — DOM API for new nodes.
  • Template literals (` `) with ${…} interpolation build HTML inline.
  • data-* attributes — custom data we read back via btn.dataset.action. Avoids per-button event listeners.
Security note: we're concatenating user-supplied URLs into raw HTML via innerHTML. For a real product, sanitise or use textContent/setAttribute to avoid XSS if the long URL contains <script>. The server already validates HttpUrl, which limits the surface, but be aware.

6. Clipboard

async function copyText(text, btn) {
  try {
    await navigator.clipboard.writeText(text);
    if (btn) {
      const original = btn.textContent;
      btn.textContent = 'Copied!';
      btn.classList.add('copied');
      setTimeout(() => {
        btn.textContent = original;
        btn.classList.remove('copied');
      }, 1200);
    }
  } catch (err) { console.error('Clipboard failed', err); }
}
Async clipboard API. navigator.clipboard.writeText returns a Promise; awaits resolution. After success, swap the button label and add the .copied class for visual feedback, then revert after 1.2 seconds. Falls into catch if the user denied clipboard permission.

8. Submit handler

form.addEventListener('submit', async (e) => {
  e.preventDefault();
  clearError();
  resultCard.hidden = true;

  const longUrl = input.value.trim();
  if (!isValidUrl(longUrl)) {
    showError('Please enter a valid http(s) URL.');
    return;
  }

  submitBtn.disabled = true;
  submitBtn.textContent = 'Shortening…';

  try {
    const data = await shorten(longUrl);
    resultLink.href = data.short;
    resultLink.textContent = data.short;
    resultCard.hidden = false;

    addToHistory(data);
    input.value = '';
  } catch (err) {
    showError('Something went wrong. Try again.');
    console.error(err);
  } finally {
    submitBtn.disabled = false;
    submitBtn.textContent = 'Shorten';
  }
});
The orchestrator.
  • addEventListener('submit', async (e) => …) — modern way to attach a handler. Arrow function so this is irrelevant.
  • e.preventDefault() — stops the browser's default form submission (full-page reload). Crucial for SPAs.
  • input.value.trim() — strip whitespace. Users paste with leading spaces.
  • submitBtn.disabled = true — prevent double-clicks while the request is in flight.
  • try / catch / finally — happy path inside try, network errors caught, button re-enabled in finally regardless. Same pattern as Python.
  • await shorten(...) — pauses this function, lets the event loop process other work. When the server replies, execution resumes on the next line.

10. Event delegation for history rows

historyList.addEventListener('click', (e) => {
  const btn = e.target.closest('button[data-action]');
  if (!btn) return;

  if (btn.dataset.action === 'copy') {
    copyText(btn.dataset.short, btn);
  } else if (btn.dataset.action === 'del') {
    deleteFromHistory(btn.dataset.code);
  }
});
One listener, many buttons. Attaching a listener to every history row would be wasteful and would re-attach on every re-render. Instead, attach once to the parent <ul>; clicks bubble up. e.target.closest(selector) walks up the DOM until it finds a matching ancestor (or null). dataset.action reads the data-action attribute.

🧪tests/test_api.py pytest + TestClient 
@pytest.fixture()

Test isolation via env var + reload.

  • monkeypatch.setenv sets TINYLINK_DB just for this test; reverted automatically afterwards.

10. Dockerfile

Recipe for building a reproducible container image.

🐳Dockerfile Docker
Build the image once; run it as many isolated containers as you like.
FROM python:3.12-slim
Pick the base. python:3.12-slim is the official Python 3.12 image on a stripped-down Debian. Much smaller than the default python:3.12 (~120MB vs ~1GB) while keeping pip and most stdlib working. 
WORKDIR /app
Set the working directory inside the container. All subsequent COPY and RUN commands act relative to /app. Also cd /app when the container starts.
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
Install deps before copying app code. Docker layer-caches each step. If only your application code changes, this layer stays cached and rebuilds are fast. If requirements.txt changes, deps reinstall — that's the trigger you want.
  • --no-cache-dir — don't keep pip's wheel cache inside the image. Smaller final size.
COPY backend ./backend
COPY frontend ./frontend
Copy the actual source last. Most-changing files in the highest layer → maximal cache use during iteration.
EXPOSE 8000
CMD ["uvicorn", "backend.main:app", "--host", "0.0.0.0", "--port", "8000"]
How to run the container.
  • EXPOSE 8000 — documentation only; doesn't actually publish the port. docker run -p 8000:8000 does that.
  • CMD ["…", …] — exec form (vs shell form). The container's PID 1 is uvicorn directly — no shell wrapping it. Signals like SIGTERM reach uvicorn cleanly so it can shut down gracefully.
  • --host 0.0.0.0 — listen on every interface, not just localhost. Without this, the port forward doesn't reach you.

11. docker-compose.yml

One file, one command, app comes up.

📦docker-compose.yml YAML 
services:
  app:
    build: .
    ports:
      - "8000:8000"
    volumes:
      - ./backend:/app/backend
      - ./frontend:/app/frontend
    environment:
      TINYLINK_DB: /app/backend/tinylink.db
The shape of compose.
  • services: — a map of named containers. app is our only one (add a cache: service later if you wire in Redis).
  • build: . — build from the Dockerfile in the current directory.
  • ports: "8000:8000" — map host port 8000 → container port 8000. Visit http://localhost:8000 on your laptop.
  • volumes: — bind-mount host directories into the container. Edits to backend/ on your laptop are seen by the running container; combined with --reload, you'd get live restart.
  • environment: — set env vars inside the container. TINYLINK_DB overrides the default DB path so the SQLite file lives in the mounted volume and survives container restarts.
Run with docker compose up --build.
